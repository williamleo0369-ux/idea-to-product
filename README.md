# 成器｜idea-to-product

**从想法到产品，从发布前判断到发布后复盘。**

成器是一套 Agent 技能包，将策划、设计、开发接成可执行的工作流，并加入文案版本比较、受众反应模拟和真实结果复盘。

你可以用它收敛一个产品想法、设计和实现核心功能，也可以单独比较两版发布文案。关键判断在验证前记录，结果出现后再对照复盘，让下一轮调整有依据。

适用于 AI 应用、网站、智能硬件配套软件、内容工具与个人作品。

作者：William Leo · 版本：0.3.0 · 许可：[MIT](LICENSE)

## 核心能力

| 能力 | 解决的问题 | 交付结果 |
|---|---|---|
| 策划 | 为谁做、解决什么、先做多少 | 产品简报、核心任务、最小范围与验收标准 |
| 设计 | 怎样让用户看懂价值并完成任务 | 用户流程、界面或原型、关键状态与开发交接 |
| 开发 | 怎样让功能实际运行 | 代码、集成、启动方式与验收证据 |
| 发布前模拟 | 哪个文案版本更适合目标受众 | 候选全文、模拟反应、相对评分与推荐稿 |
| 预测与复盘 | 判断是否被真实结果支持 | 事前记录、证据对照、决策更新与下一实验 |

已有简报可以直接设计，已有设计可以直接开发；只需要比较文案时，也能直接进入发布前模拟。确定性小修只做验收，不强制增加实验。

## 快速开始

下载或克隆本仓库，在仓库根目录执行：

```bash
python3 scripts/install.py
```

安装器使用 Python 3 标准库，将四个技能安装到 `$CODEX_HOME/skills`；未设置 `CODEX_HOME` 时使用 `~/.codex/skills`。任一同名目标已存在时停止，不覆盖已有内容。更新前先备份或移走原来的四个技能目录，再重新安装。

安装后，在支持技能的客户端中输入：

```text
用 $idea-to-product 做一个给乐器博主用的动态曲谱工具。
先做本地网页版，支持手动校正时间轴和导出透明视频。
完成策划、设计和开发，并列出需要验证的关键假设。
```

或从一条文案开始：

```text
用 $idea-to-product 比较下面两版产品介绍。
受众是独立开发者，目标是吸引有具体需求的人来咨询。
模拟受众反应，推荐一版，并说明发布后怎样验证。
```

其他支持 `SKILL.md` 的 Agent 可将技能目录复制到其支持的位置。调用语法与自动发现方式以客户端为准；实际实现需要文件、终端等工具，视觉验收需要可用的预览工具。

## 四个技能入口

| 入口 | 用途 |
|---|---|
| `$idea-to-product` | 总入口：阶段衔接、文案模拟、预测、复盘与状态查询 |
| `$idea-to-product-plan` | 策划：目标、需求、对标、价值与产品范围 |
| `$idea-to-product-design` | 设计：流程、界面、视觉与内容表达 |
| `$idea-to-product-develop` | 开发：实现、集成、修复与运行验证 |

总入口按需读取三个相邻技能。子技能可独立复制安装；完整模拟协议、实验协议、模板和登记脚本随总入口提供。缺少总入口时，子技能使用自身的简化比较和记录说明。

```text
用 $idea-to-product-plan 把“用 AI 帮小商家做内容”收敛成可验证的产品。

用 $idea-to-product-design 改进现有应用的首次使用流程，保留品牌风格。

用 $idea-to-product-develop 按已有设计实现上传、预览和导出，验证失败状态。
```

## 工作流程

**策划 → 设计 → 开发 → 发布前模拟 → 事前预测 → 实际验证 → 复盘 → 调整对应板块。**

这条流程按任务选择，不要求每次从头跑完。产品的需求、体验和技术假设可以在各阶段独立验证；文案模拟可以提前用于价值主张、首屏表达，也可以用于开发完成后的产品演示。

| 阶段 | 可比较或预测的对象 | 真实验证依据 | 反馈到哪里 |
|---|---|---|---|
| 策划 | 用户问题表达、价值主张、试用或付费假设 | 访谈、试用、真实交易 | 用户、价值、范围与商业链路 |
| 设计 | 标题、首屏、行动入口、任务完成预期 | 用户任务测试、耗时、错误与反馈 | 信息结构、流程、状态与文案 |
| 开发 | 已实现功能的演示表达、性能与可靠性目标 | 实测日志、输出文件与失败测试 | 实现、依赖与技术范围 |
| 内容发布 | 开头、正文、行动入口与表现预期 | 发布后的留存、互动与有效咨询 | 受众假设、表达规则与下一内容版本 |

## 发布前：比较版本，模拟受众反应

输入两版推文、标题、视频开头或产品文案。只有一版时保留原稿并生成候选；只有想法时生成 2–3 个版本。

Agent 使用相同的受众视角与目标评估各版本，交付：

- **候选全文**：保留编号与版本，改稿另建新编号。
- **模拟反应**：理解、继续阅读倾向、互动理由、反对意见与退出点。
- **比较依据**：问题清晰度、证据与可信度、阅读推进、行动匹配。
- **推荐稿**：可直接使用的文本，以及推荐和未推荐理由。
- **验证计划**：发布后看什么指标、观察多久、什么结果会推翻判断。

```text
用 $idea-to-product 为这条演示视频生成三个开头。
目标是让乐器博主理解工具用途，模拟受众反应后推荐一版。
```

例如，以“吸引有需求的人来咨询”为主目标时，高争议、容易引发评论的版本不一定优于能清楚说明使用场景和入口的版本。

模拟结果的解释随证据而变化：

| 证据等级 | 可输出什么 |
|---|---|
| 无可比历史数据 | 相对倾向、原文依据、编辑评分与未知项 |
| 有可比历史数据 | 样本来源、历史中位数与范围，以及可比性限制 |
| 已有校准与误差评估 | 在说明规则版本、评估口径和误差依据后，输出适用的数值预测 |

模拟评论均标为 AI 假设，不代表真实用户意见。编辑评分不等于成功概率，角色赞同票数不换算为真实互动比例。这是发布前模拟预检，不是真实投放 A/B 实验；只发布一个版本时，只能检验该版本，不能证明其他版本更差。

查看 [发布前模拟协议](skills/idea-to-product/references/preflight.md)、[比较报告模板](skills/idea-to-product/templates/preflight.md)和 [完整比较示例](examples/preflight.md)。

## 验证前：固定事前判断

在看到该次实验或作品的结果前，记录输入版本、目标、指标、样本范围、观察窗口、预期、依据与否证条件。

```text
用 $idea-to-product 为最终发布稿登记事前预测，关联刚才的比较报告。

用 $idea-to-product 为这版设计登记任务完成率实验，先记录预期再开始测试。
```

产品实验可以约定“5 名目标用户中至少 4 人无需提示完成导入”，再用全部样本检验。这是实验目标示例，不代表已测结果或通用标准。

没有历史数据时写可证伪判断与不确定性，不编造播放量或成功概率。已经看过该次结果时，记录事后回顾并标记 `reconstructed`，不能补写盲预测。

## 验证后：复盘并更新决定

按事前口径收集真实数据，对照原判断，判定支持、否证、证据不足或待验证，再决定继续、调整、停止或等待。

```text
用 $idea-to-product 复盘 design-01。
这是完整任务测试记录，请对照原预测并更新设计决策。

用 $idea-to-product 复盘这条发布内容。
这是发布链接和约定窗口的数据，请指出预测偏差与下一次实验。

用 $idea-to-product 查看待验证项、缺失证据和下一步。
```

原预测保留，复盘另存。修改规则时保留版本与证据；回测不算事前预测，小样本观察不当作已验证规律。没有真实样本时保留验证待办，不以交付完成代替验证通过。

产品与内容采用不同指标：

| 对象 | 指标示例 |
|---|---|
| 产品 | 任务完成率、激活、留存、付费、退款、性能与成本 |
| 内容 | 观看留存、阅读完成、收藏、有效咨询 |

播放量不能证明付费需求，试用意愿不等于成交。内容简化模式默认在发布后 3 天复盘，可调整窗口；状态查询不会自动建立提醒。

查看 [产品实验闭环](skills/idea-to-product/references/experiments.md)、[内容校准协议](skills/idea-to-product/references/calibration.md)、[预测模板](skills/idea-to-product/templates/prediction.md)和 [复盘模板](skills/idea-to-product/templates/retro.md)。

## 方法来源与整合方式

| 来源 | 本包采用的思路 |
|---|---|
| DBS | 明确目标与交付物，分析用户问题、对标和商业链路 |
| CrowdTest 的公开功能描述 | 发布前比较文案版本，模拟受众反应，辅助选择 |
| cheat-on-content | 事前判断与实绩分离，保留预测，用复盘证据校准判断 |

本包独立可用，不要求安装上述技能，也不调用 CrowdTest 服务或复现其私有算法。三个产品板块的实验协议与文案模拟尺度由本包独立编写。

已安装 DBS 或 cheat-on-content 且需要专项能力时，Agent 按需读取并遵循其实际协议。使用完整 cheat 流程时，沿用其初始化、评分、预测、状态与审核规则，复用原日志，避免重复创建预测体系。

本包提供简化内容校准，没有内置已校准的流量公式。具体来源与范围见 [SOURCES.md](SOURCES.md)。

## 文件与记录

仓库中的技能包结构：

```text
skills/
├── idea-to-product/             总入口、协议、模板与登记脚本
├── idea-to-product-plan/        策划
├── idea-to-product-design/      设计
└── idea-to-product-develop/     开发
```

持续项目按需在自己的工作目录保存：

```text
.idea-to-product/
├── brief.md                    策划与假设
├── design.md                   设计与交接
├── delivery.md                 运行与验收
├── status.json                 阶段、实验与下一动作
├── decisions.md                复盘后的决策更新
├── experiments/
│   ├── predictions/            产品实验事前记录及 SHA-256
│   └── retros/                 产品实验复盘
└── content/
    ├── preflights/             文案版本比较报告
    ├── predictions/            简化模式的内容事前预测
    ├── publications/           发布登记
    └── retros/                 内容复盘
```

已有产品、设计或运行文档优先复用，源码留在原项目结构。完整 cheat 模式的内容预测与发布复盘沿用上游目录。字段见 [项目记录契约](skills/idea-to-product/references/project-records.md)。

### 产品实验登记脚本

Agent 可以按模板创建记录，也可以填写模板后使用仓库中的脚本：

```bash
python3 skills/idea-to-product/scripts/record.py predict design-01 /path/to/filled-prediction.md --project /path/to/project

python3 skills/idea-to-product/scripts/record.py retro design-01 /path/to/filled-retro.md --project /path/to/project --revision 1
```

替换示例路径。ID 与复盘版本只接受字母、数字、下划线及连字符。脚本用于产品实验记录，拒绝覆盖已有文件，并在登记复盘时检测预测原文哈希；它不验证内容真实性或预测盲度，也不是强制防篡改 hook。

没有事前预测的回顾独立保存为 `reconstructed`，不使用要求原预测存在的 `retro` 命令。

在仓库根目录运行：

```bash

```

检查覆盖技能结构、相对引用、安装器防覆盖、预测保留与哈希检测，不代表产品效果或内容预测能力已经通过实战验证。
