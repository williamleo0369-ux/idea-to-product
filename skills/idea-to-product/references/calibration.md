# 内容与产品验证

## 两种模式

- 安装了 cheat-on-content 且用户要使用它：完整读取其入口；首次执行先运行其 init；按上游路由执行预测、发布、复盘和 bump。复用其已有文件，不创建第二份预测体系。上游需要独立盲评或跨模型审核而工具不可用时明确限制，不把自审写成独立审核。
- 没有安装或用户只需要简化验证：使用下述 idea-to-product 循环，明确不是完整 cheat-on-content 实现，不宣称有其 hook、7 维评分或已校准公式。

## 发布前先比较版本

需要选择文案、标题、开头或行动入口时，先执行 [发布前模拟](preflight.md)，交付多版文本、相同受众视角的模拟反应、相对评分和推荐理由。模拟反应不是实绩；最终稿另写一次预测并关联预检 ID 与版本哈希。只发布一版时不声称验证了所有候选的排序。

## 先把实际能力变成内容

优先制作“真实问题 → 实际操作 → 结果 → 使用边界 → 一个行动入口”的演示。标题、封面和文案只使用可证明事实。按目标平台与内容形态写稿；公开平台规则、价格和产品能力需要查当前官方资料。

可以用 1–5 分分别诊断问题清晰度、证据强度、表达效率、行动匹配度。每项附具体段落依据与一个改进动作；这是编辑启发，不是流量模型。没有数据不填成功概率、播放量区间或因果结论。

## 事前与事后分离

未发布且预测者未见该作品实绩，才创建 `.idea-to-product/content/predictions/<id>.md`。记录时间、内容版本（文件哈希或 Git commit）、规则版本、目标受众、主指标、观察窗口、事前判断、依据与不确定性。有可比历史样本才给数值区间，说明样本口径；冷启动只写方向性判断和可证伪条件。

任何该作品发布后数据、具体评论或后台截图已被看到，就写 `.idea-to-product/content/retros/<id>.md` 并标记 reconstructed；不补写事前预测，也不计入盲预测准确率。已发布但没见数据也只做前瞻实验建议，不倒签发布前预测。

预测文件写完后不编辑、不删除；笔误在复盘说明。改稿后如仍未发布且没有实绩，另建修订预测，关联旧 ID 和新内容版本。默认没有强制防篡改机制；必要时用 Git 提交固定基线，不声称系统自动保护。

发布登记另存 `.idea-to-product/content/publications/<id>.md`：真实 URL、发布时间及时区、内容版本。登记不等于执行社交发布。

到约定窗口（内容默认发布时间后 3 天，可按平台调整）读取或请求真实数据，不擅自建立定时任务。复盘独立保存于 `retros/`，记录来源、采集时间、窗口、预测引用、实绩、偏差和下一次实验。尚未到窗口或数据缺失，标为待复盘。

## 分开验证

| 对象 | 主指标示例 | 不能推出 |
|---|---|---|
| 内容 | 观看留存、阅读完成、收藏、有效咨询 | 产品已获付费验证 |
| 产品 | 核心任务完成率、激活、留存、付费、退款 | 某条内容必然有流量 |

产品指标要写分母、样本量、时间窗口、事件定义。复盘关注能行动的原因假设；多个变量同时变动时不把效果归因于其中一个。

## 更新规则

简化模式把新规则写成候选版本，在所有同口径、数据完整的历史样本上比较新旧规则；保留原预测，只新增回测结果。明确比较指标和排除样本理由；未改善则保留旧规则。至少留一个未来样本做前瞻验证，标记“待校准”。小样本只记观察，不把拟合当泛化能力。

完整 cheat 模式遵循其全量重算、排序验证、独立审核和清理协议，不用本包简化流程替代。经过验证并合并的观察从当前规则备忘中移除，历史通过版本记录保留。
