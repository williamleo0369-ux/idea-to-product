# 发布前模拟：多版本文案与受众反应

功能参考 CrowdTest 的公开描述：发布前输入不同版本、模拟受众反应、比较并选择。这里实现的是 Agent 文案预检工作流，不调用 CrowdTest、不复现其私有算法、不声称训练了用户行为模型。

## 输入与启动

从已有材料读取平台、账号阶段、目标受众、发布目的、真实产品能力、约束、草稿和可比历史数据。缺失时仅补决定比较口径的信息。只给一版就保留原稿 A 并生成 B；只给想法就生成 2–3 版。用户给了多版就先比较这些，不擅自全部替换。

选择一个主目标：传播、收藏、讨论或有效咨询/转化；其他目标为辅助。变更多个因素的方案比较称“多版本模拟预检”，不能称为真实随机 A/B 实验。要测试单因素时固定正文，只变标题、开头、证据呈现或行动入口之一。

冻结候选文本、编号和文件哈希，记录上下文与规则版本。已经看过某版实绩时，其数据只作历史依据；新候选单独编号，不能倒写原版的盲预测。

## 受众视角

基于提供的受众资料选 3–5 个有区别的视角，例如：目标需求用户、第一次看到账号的人、熟悉领域的人、持怀疑态度的人。用户资料不足时明确“以下为假设受众”，不编造年龄、收入、购买习惯或人口比例。

同一组视角对所有版本使用相同问题：

1. 第一眼理解了什么，是否有继续看下去的理由？
2. 哪个具体句子可信，哪里需要证据或容易被误解？
3. 可能愿意点赞、收藏、评论或转发的理由是什么？
4. 是否理解行动入口，是否产生有价值的下一动作？
5. 最可能的反对意见或退出点是什么？

用“倾向 / 不确定 / 不倾向”加原文依据记录。生成的反应、评论均标为模拟，不当作真实用户证言。单 Agent 分别扮演视角不是独立用户采样或独立模型审核；未经用户授权不启动额外 Agent。没有真实采样就不写“模拟了千万人”。

## 同口径比较

使用 [比较模板](../templates/preflight.md)。相对评分默认四维 1–5 分：问题清晰度、证据与可信度、阅读推进、主目标行动匹配。每项给原文锚点；同尺度比较，避免靠汇总分掩盖事实错误。需要总分时等权平均并标记为编辑启发分，不是互动率、成功概率或已验证公式。接近的版本明确证据不足，不硬排第一。

输出包括候选全文、受众反应表、四维比较、各版优势/反对点、推荐稿、推荐与不推荐理由，以及下一次真实检验的指标、窗口和否证条件。主目标优先：高争议互动不自动优于有效咨询。先修虚假承诺，再推荐；不得为了分数加入用户没有的成绩或客户案例。

可以改进推荐版，但必须另编号，例如 C，说明修改及重新比较结果，不能把修改后的稿子当作已经评分的 B。

## 互动预测的证据等级

- heuristic：没有同账号、同平台、同形态的历史数据。仅给相对倾向、理由、范围与未知项，不输出点赞、评论、转发、播放数或爆款概率。
- historical-baseline：有可比历史样本。列出样本来源、数量、发布时间、观察窗口、曝光分母与差异；可给历史中位数和范围，明确是基线而非本次承诺。要输出候选数值预测，必须说明计算依据、误差验证与限制；没有这些就停在基线。
- calibrated：已有可追溯事前预测与对应实绩，并在独立留出或未来样本评估误差。标明模型/规则版本、数据量、评估口径和区间覆盖；不能只因能引用旧数据就称已校准。

“AI 模拟评论”可以帮助发现误解；“预测点赞数”需要数据与校准。不能由角色赞同票数推算真实人群比例。

## 固定判断与事后检验

生成比较报告保存在用户项目 `.idea-to-product/content/preflights/<id>.md`；小任务可先直接交付，用户要登记时再落盘。准备正式发布时读取 [内容校准](calibration.md)，为最终版本写一次事前预测，关联比较报告、文本哈希和选定版本。

完整 cheat 模式下，预检报告作为前置编辑产物。独立盲评仅接收上游允许的原稿和评分资料，不将假设受众、偏好版本或已见实绩送进盲评；遵守上游隔离要求。发布登记与复盘复用上游日志，不另写第二份内容预测。

简化模式按约定窗口比较最终发布版本的实绩与其预期，检查内容哈希是否匹配；发布稿有变动就记录偏离，不静默归因于原稿。只发布一个版本，只能检验该版本的预期，不能断言未发布版本一定更差。多个版本都发布但曝光、人群、时间不同，就记录混杂；真实 A/B 需可比或随机分配，并事前定义分母与判定规则。

将误解、行动匹配或预测偏差写回受众假设、表达规则或下一实验，保留原比较与原预测。更新规则沿用内容校准协议，不用一次爆款证明模拟准确。
